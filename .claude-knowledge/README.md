## 🎯 Назначение системы | System Purpose

Эта система представляет собой **RAG-подобную архитектуру** (Retrieval-Augmented Generation) для хранения, организации и использования дополнительных знаний, инструкций и возможностей для Claude Code.

**Основные принципы**:
- 📚 Не всё должно быть встроено в нейросеть
- 📁 Знания хранятся в структурированном текстовом формате
- 🔄 Легко читаемые, копируемые и исполняемые инструкции
- 🚀 Расширяемая архитектура для новых возможностей
- 🔌 Интеграция с MCP-протоколом, агентами и скиллами

## 🔧 Типы хранимых знаний | Knowledge Types

### 1. **Инструкции (Instructions)**
Пошаговые руководства для выполнения конкретных задач:
- Форматы: Markdown (.md), YAML (.yml), JSON (.json)
- Структура: четкие шаги, примеры, контрольные списки
- Примеры: инструкции по настройке CI/CD, паттерны проектирования

### 2. **Агенты (Agents)**
Специализированные агенты для автоматизации задач:
- Форматы: Markdown с метаданными, YAML-конфигурации
- Содержание: описание задач, параметры, зависимости
- Примеры: агент для рефакторинга, агент для документирования

### 3. **Скиллы (Skills)**
Расширенные возможности Claude Code:
- Форматы: Markdown с промптами, JSON-конфигурации
- Содержание: описание скилла, параметры, примеры использования
- Примеры: custom commit messages, specialized testing

### 4. **Шаблоны (Templates)**
Готовые шаблоны для быстрого старта:
- Форматы: исходный код, конфигурационные файлы
- Содержание: базовая структура, комментарии, параметры
- Примеры: шаблоны API, микросервисов, компонентов

### 5. **Примеры (Examples)**
Рабочие примеры и образцы кода:
- Форматы: исходный код с комментариями
- Содержание: полнофункциональные примеры, снипеты
- Примеры: интеграции с API, алгоритмы, паттерны

### 6. **Интеграции (Integrations)**
Подключение внешних систем:
- Форматы: конфигурации, скрипты, документация
- Содержание: настройки MCP, API-ключи, эндпоинты
- Примеры: MCP file system, database connectors

## 📝 Стандарты форматирования | Formatting Standards

### Структура файлов инструкций

```markdown
# Название инструкции

**Категория**: coding/architecture/testing/etc
**Уровень сложности**: beginner/intermediate/advanced
**Время выполнения**: ~XX минут
**Теги**: #tag1 #tag2 #tag3

## Описание
[Краткое описание задачи]

## Предварительные требования
- Требование 1
- Требование 2

## Пошаговая инструкция

### Шаг 1: [Название]
[Подробное описание]
```code
// Пример кода
```

### Шаг 2: [Название]
[Подробное описание]

## Результат
[Ожидаемый результат]

## Проверка
- [ ] Проверка 1
- [ ] Проверка 2

## Возможные проблемы и решения
- **Проблема**: описание
  **Решение**: решение

## Дополнительные ресурсы
- [Ссылка 1](url)
- [Ссылка 2](url)
```

### Структура конфигурации агента

```yaml
agent:
  name: "agent-name"
  version: "1.0.0"
  description: "Описание агента"

capabilities:
  - capability1
  - capability2

parameters:
  param1:
    type: string
    required: true
    description: "Описание параметра"

tools:
  - Read
  - Write
  - Bash

prompts:
  system: |
    Системный промпт для агента

  task: |
    Промпт для выполнения задачи

examples:
  - input: "пример входных данных"
    output: "пример выходных данных"
```

### Структура скилла

```markdown
# Skill: [Название]

**Type**: command/automation/helper
**Trigger**: /skill-name или автоматический
**Version**: 1.0.0

## Описание
[Что делает этот скилл]

## Параметры
- `param1` (обязательный): описание
- `param2` (опциональный): описание

## Использование
```bash
/skill-name param1 param2
```

## Промпт
```
[Полный промпт для скилла]
```

## Примеры
### Пример 1
Input: `/skill-name value1`
Output: [результат]

## Интеграция с Claude Code
[Как этот скилл интегрируется]
```

## 🚀 Использование системы | System Usage

### Метод 1: Прямое чтение инструкций

Claude Code может напрямую читать файлы из `.claude-knowledge/`:

```
User: "Покажи мне инструкцию по настройке CI/CD"
Claude: [Читает .claude-knowledge/instructions/deployment/ci-cd-setup.md]
```

### Метод 2: Интеграция через Memory

Ссылки на часто используемые инструкции в `~/.claude/projects/[project]/memory/MEMORY.md`:

```markdown
# Project Memory

## Knowledge Base
- CI/CD Setup: see .claude-knowledge/instructions/deployment/ci-cd-setup.md
- Testing Patterns: see .claude-knowledge/instructions/testing/patterns.md
```

### Метод 3: Автоматическое обнаружение

Claude Code автоматически сканирует `.claude-knowledge/` при:
- Старте сессии
- Упоминании ключевых слов (instructions, examples, templates)
- Запросе помощи по специфичным задачам

### Метод 4: MCP-интеграция

Использование MCP-сервера для доступа к файловой системе:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem",
               "/home/user/project/.claude-knowledge"]
    }
  }
}
```

### Метод 5: Custom Skills

Создание кастомного скилла для быстрого доступа:

```bash
/knowledge search "CI/CD"
/knowledge show instructions/deployment/ci-cd-setup.md
/knowledge list templates
```

## 🔄 Жизненный цикл знаний | Knowledge Lifecycle

### 1. Создание (Creation)
- Определение потребности в новом знании
- Выбор подходящей категории и формата
- Создание по стандартному шаблону
- Добавление метаданных и тегов

### 2. Валидация (Validation)
- Проверка корректности инструкций
- Тестирование примеров кода
- Проверка форматирования
- Ревью и утверждение

### 3. Использование (Usage)
- Доступ через Claude Code
- Применение в реальных задачах
- Сбор обратной связи

### 4. Обновление (Update)
- Актуализация информации
- Исправление ошибок
- Добавление новых примеров
- Версионирование изменений

### 5. Архивирование (Archive)
- Перемещение устаревших знаний
- Сохранение истории
- Документирование причин устаревания

## 🔒 Безопасность | Security

### Правила безопасности:
1. **НЕ храните чувствительные данные**:
   - API ключи
   - Пароли
   - Токены доступа
   - Приватные сертификаты

2. **Используйте переменные окружения**:
   ```markdown
   API_KEY: ${ENV:API_KEY}
   ```

3. **Добавьте в .gitignore**:
   ```
   .claude-knowledge/.secrets/
   .claude-knowledge/.credentials/
   ```

4. **Шифрование**:
   Для критичных данных используйте шифрование

## 📚 Лучшие практики | Best Practices

### ✅ DO (Делайте):
- Используйте четкие, описательные имена файлов
- Добавляйте метаданные и теги
- Пишите примеры использования
- Документируйте предварительные требования
- Обновляйте дату последнего изменения
- Используйте семантическое версионирование
- Проверяйте код примеров перед сохранением
- Добавляйте ссылки на дополнительные ресурсы

### ❌ DON'T (Не делайте):
- Не дублируйте информацию
- Не храните большие бинарные файлы
- Не используйте абсолютные пути
- Не пишите слишком длинные инструкции (разбивайте)
- Не забывайте про форматирование
- Не оставляйте устаревшую информацию
